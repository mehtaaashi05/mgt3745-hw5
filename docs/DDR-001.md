## 6. Findings

**Pass count:** 4 of 4 EARS rows (final integrated page), 5 of 5 code-eval tests, and 11 of 12 judgment questions.

**Observed in bolt's output, and what I did:**

- The generated app used a React/Tailwind stack instead of the existing static-file architecture. I rebuilt it directly into the project’s three existing files.
- The original output used default palette values and a gold accent that violated the STYLE.md contrast requirement. I replaced those with the repo tokens and kept the gold accent only as a border accent.
- The generated CSS included an animation and a default font import that the repo explicitly rejects. I removed both.
- The generated app used a default developer label and a shadowed `list` variable. I replaced the label with user-facing content and renamed the variable to keep the output clean.
- The zip included `@supabase/supabase-js` and unused dependency noise. None of it was carried into the repo.

**Problems introduced or found during integration:**

- The guide tokens were first scoped too locally; I moved them to the root design tokens so the repo remained aligned with the existing directory styling.
- The gold text treatment failed contrast when it was placed on white. I changed it back to the approved primary blue for text and kept gold just for the accent border.
- I checked the final tokens against the style specification and removed any drift from the default bolt palette.
- The feature content is hardcoded in `app.js`, which matches the requirement that F-04 is a static guide and does not require a new storage layer.

**Could not fully verify:** the exact model name exposed by bolt.new and the full set of transitive licenses in the original zip. I did not run an install for the unzipped output; I limited the risk by preserving only the reviewed repo files and documenting the gap here instead of claiming the generated project itself was clean.
